# Представление данных в S-выражениях

## Постановка задачи

Цель работы - разработать библиотеку для хранения, поиска, изменения и проверки древовидных данных. В качестве дополнительной функциональности выбрано преобразование данных в HTML.

### Базовые требования

- формат документа в S-выражениях с элементами, атрибутами и текстовым содержимым;
- язык запросов с абсолютными и относительными путями, условиями на свойства промежуточных узлов и поиском потомков на произвольной глубине; поиск и модификацию данных через этот язык;
- описание схем и проверку документов: типы и обязательность атрибутов, порядок и количество дочерних элементов.

### Выбранное дополнительное требование

- язык трансформации данных в HTML как упрощённый аналог XSLT: HTML-шаблоны с выводом значений, условиями, перебором и применением правил к выбранным элементам.

Показать на демонстрационном примере каталога книг базовую функциональность: проверить данные по схеме, выбрать книги заданного года и изменить атрибут одной книги. В рамках дополнительной функциональности сформировать HTML-страницу.

## Теоретическая основа и способы решения

S-выражения позволяют описывать вложенные структуры с помощью атомов и списков. В работе используются расширенные формы Clojure: элемент представляется вектором, атрибуты - отображением, содержимое - вложенными элементами и строками. Семантическими аналогами служат XML и JSON, в которых составные данные также можно рассматривать как дерево.

Возможны два подхода к обработке документов. **Дерево в памяти**, как в модели DOM, позволяет многократно обращаться к любым узлам и изменять структуру. **Потоковая обработка**, как в SAX, требует меньше памяти, но не предоставляет произвольного доступа к уже прочитанным узлам. Для проекта выбирается первый подход, поскольку необходимы запросы и модификации дерева.

Основой языка запросов служат идеи XPath: путь задаёт последовательность переходов, а условия отбирают подходящие узлы. Запросы можно выполнять последовательным обходом дерева; для повторного поиска допустим индекс расположения узлов. Проверка по схеме, по аналогии с XML Schema, сопоставляет структуру документа с правилами типов, порядка и количества элементов.

Преобразование в HTML строится по образцу XSLT: шаблоны определяют, какие выходные элементы создаются для выбранных входных узлов. Возможна интерпретация правил либо их предварительное преобразование в исполняемые функции. В проекте выбирается интерпретация запросов и шаблонов, записанных как данные Clojure. Документы читаются в формате EDN без выполнения кода. Модификация неизменяемых структур возвращает новое дерево, сохраняя исходное.
