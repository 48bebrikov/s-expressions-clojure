# Представление данных в S-выражениях

**Авицинов Антон 26225, Галич Ирина 26225**

## 1. Постановка задачи

**Цель работы** — разработать библиотеку для представления и обработки данных с древовидной структурой в виде S-выражений, обеспечивающую навигацию по дереву, поиск и модификацию узлов, проверку документов на соответствие заданной схеме, а также преобразование данных в формат HTML.

Для достижения поставленной цели необходимо решить следующие задачи:

1. Разработать формат представления древовидных данных в виде S-выражений.
2. Разработать язык навигации и запросов, реализовать поиск и модификацию данных с его помощью.
3. Разработать формат описания схем и реализовать проверку документов на соответствие заданным ограничениям.
4. Провести модульное и интеграционное тестирование разработанной библиотеки.

В качестве дополнительного требования выбрана разработка языка трансформации данных в HTML как упрощённого аналога XSLT.

## 2. Теоретическая основа и способы решения

S-выражения позволяют описывать вложенные структуры с помощью атомов и списков. В работе планируется использовать расширенные формы S-выражений, применяемые в Clojure: элементы будут представляться векторами, атрибуты — отображениями, а содержимое — вложенными элементами и текстовыми значениями. Семантической основой формата послужат XML и/или JSON, данные которых могут быть представлены в виде дерева.

Для обработки документов рассматриваются два подхода:

- **Древовидное представление в памяти (аналог DOM)** — позволяет обращаться к произвольным узлам документа, выполнять поиск и изменять структуру.
- **Потоковая обработка (аналог SAX)** — позволяет обрабатывать данные последовательно с меньшими затратами памяти, но не обеспечивает произвольного доступа к уже обработанным узлам.

В рамках работы выбирается первый подход, поскольку разрабатываемая библиотека должна поддерживать навигацию, поиск и модификацию произвольных узлов дерева.

Основой языка запросов послужат идеи XPath: путь задаёт последовательность переходов по дереву, а условия позволяют отбирать узлы по заданным свойствам. Для выполнения запросов будет использоваться обход дерева.

Формат описания схем будет разработан по аналогии с XML Schema. Проверка документа будет заключаться в сопоставлении его структуры с заданными ограничениями на состав элементов, атрибуты, типы значений, количество и порядок дочерних узлов.

Преобразование данных в HTML будет реализовано по аналогии с XSLT. Для этого будет разработан язык шаблонов, определяющий правила преобразования исходных узлов в HTML-элементы.

В качестве технологической основы планируется использовать язык Clojure. Документы и описания схем будут представлены в виде структур данных Clojure. Для чтения входных данных может использоваться формат EDN без выполнения произвольного кода. Модификация неизменяемых структур будет осуществляться с формированием нового дерева.

## 3. План выполнения работы

### Этап 1. Проектирование формата данных

**Цель:** определить способ представления XML/JSON-подобных деревьев в виде S-выражений.

Необходимо:

- определить структуру представления узлов дерева;
- определить способы представления имён узлов, атрибутов, текстового содержимого и дочерних элементов;
- определить правила вложенности и допустимые типы значений;
- определить набор и интерфейсы базовых операций для работы с выбранным форматом.

### Этап 2. Реализация базовых операций с S-выражениями

**Цель:** обеспечить возможность создания и обработки древовидных структур.

Необходимо реализовать:

- создание узлов;
- получение имени узла и его атрибутов;
- получение дочерних элементов;
- добавление и удаление узлов;
- изменение атрибутов и содержимого;
- обход дерева.

### Этап 3. Разработка языка навигации и запросов

**Цель:** разработать собственный упрощённый аналог XPath.

Необходимо:

- определить синтаксис и семантику языка запросов;
- предусмотреть абсолютные и относительные пути к узлам;
- реализовать условия на свойства промежуточных узлов;
- предусмотреть поиск потомков на произвольной глубине вложенности;
- реализовать разбор выражений языка запросов;
- реализовать поиск узлов и их модификацию посредством разработанного языка.

### Этап 4. Разработка представления схем и механизма валидации

**Цель:** создать упрощённый аналог XML Schema.

Необходимо:

- определить формат описания схем;
- предусмотреть описание допустимых узлов;
- определить обязательные и необязательные атрибуты;
- определить допустимые типы значений;
- предусмотреть ограничения на количество и порядок дочерних элементов;
- реализовать проверку документов на соответствие заданным схемам;
- обеспечить формирование сообщений об ошибках валидации с указанием их характера и местоположения.

### Этап 5. Разработка языка трансформации в HTML

**Цель:** реализовать упрощённый аналог XSLT.

Необходимо:

- определить формат и синтаксис правил трансформации;
- предусмотреть сопоставление узлов исходного дерева с HTML-элементами;
- реализовать вывод текстовых значений и атрибутов;
- предусмотреть условия и перебор элементов;
- реализовать применение правил трансформации к выбранным узлам;
- обеспечить формирование итогового HTML-документа.

### Этап 6. Тестирование

**Цель:** проверить корректность работы отдельных компонентов и библиотеки в целом.

Необходимо:

- проверить создание, чтение и модификацию древовидных структур;
- протестировать все поддерживаемые конструкции языка запросов;
- проверить поиск при отсутствии совпадений;
- проверить корректность модификации найденных узлов;
- протестировать валидацию корректных и некорректных документов;
- проверить обработку ошибок и граничных случаев;
- протестировать преобразование данных в HTML;
- провести интеграционное тестирование всех компонентов.

## 4. Демонстрационный пример

- поиск элементов документа по заданным условиям;
- изменение атрибутов выбранных элементов;
- преобразование документа в HTML-страницу с использованием разработанного языка трансформации.
